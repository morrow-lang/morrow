* **Status**: Adopted; measured comparisons are recorded separately in the [actor benchmark](../benchmarks/language-comparison/ACTORS.md)
* **Decision**: Split eligible native actor straight-line prefixes at a threshold of 32 source computations, including transitive finite helper costs. Preserve ordinary helper ABIs. `MORROW_REDUCTIONS=1..65536` sets resumable callbacks per actor turn, default 1; a trampoline returns from each callback before entering the next, and receive always ends the turn. This is compiler safepoint scheduling, not interruption of native stacks. Control scaffolding and frame construction add work beyond the source count; native primitives, FFI, sort comparators, cleanup, receive guards and unsupported resource-bearing helper paths remain synchronous. Copying and GC are not reduction-metered, and WASM actors remain unsupported.
* **Ownership**: Opt-in `MORROW_WORK_STEALING=1` uses owner-assisted donation. Idle schedulers request work from owners advertising surplus eligible queued actors; only the source owner inspects or mutates its queue. At a callback boundary it precisely collects the candidate heap before acquiring transport locks, then detaches the remaining actor heap, preserves block addresses and immutable PID identity, and transfers exclusive heap ownership to the destination endpoint. Adoption assigns a fresh local heap ID and identity slot, updates the actor's execution context and retained session, and moves local live/message/byte bookkeeping without changing invocation-wide admission. Heap bytes stay physically charged to the source until adoption or drop; retained external controls keep their originating accounting. Active scopes, native frames, additional roots, known foreign heap edges or exhausted validation work decline a move atomically. A donation attempts at most four bounded heap validations. Collection itself is not covered by that work bound; a declined donation may reclaim unreachable storage while leaving source ownership and registrations intact. Profiling identified dead continuation storage as the dominant request/reply migration cost; an independent regression checks reclamation before transport locking and retention of the live graph. Successful adoption and declined detach start a 256-owner-turn cooldown before another automatic donation attempt; new actors remain immediately eligible. Idle polling does not age that cooldown, and a thief does not request work while its own endpoint already has pending commands.
* **Routing and retirement**: Each actor has synchronized ingress storage outside the collector's scanned control region. Send publication and route changes serialize; pending copied messages retain FIFO order during transfer. Notices only wake an owner, and stale notices never read foreign payload fields. Liveness is checked under the routing lock before publication, closing the finish-versus-send race that otherwise strands an ingress ownership cycle. Stop prevents new transfer publication under the activity lock; already queued transfers are adopted even during stop so destination cleanup executes admitted defers exactly once. Dead controls remain valid through stale PIDs.
* **Resource policy**: Host ports and supervised actors stay pinned; the latter retain a separate initializer heap and owner-local restart state. Any arbitrary foreign call or access to the thread-local compatibility actor API permanently pins the active actor before resource access. A thread-confined guard restores the callback-affinity cursor on return, including selectors and cancellation cleanup. This cursor only records affinity; language execution still uses explicit `Exec`. Native embedders must call `morrow_managed_pin_current()` before accessing other thread-affine resources. SQLite connections already use a process-wide mutex. Integer values alone cannot prove that a foreign resource is transferable.
* **Drivers and compatibility**: The root run driver never parks while its local run queue is ready. The first actor benchmark exposed a preexisting 10 ms wait after each 64-turn poll, which made a migrated CPU actor take minutes; a 129-callback regression fails with two waits before the fix and passes with zero afterward. Failed-detach retry and immediate migration-bounce regressions separately establish the cooldown policy. Stealing defaults off; single-callback quanta preserve existing default traces. Production and deterministic scheduler-set drivers execute the same donation, handoff and adoption code. Simulation records scheduler choices, and `simulated_work_stealing` configures stealing before admission. Replay establishes logical ownership/order invariants; physical thread races require separate sanitizer coverage. Unsupported native work and pinned resources remain explicit limits rather than claims of BEAM/OTP parity.
* **Acceptance**: The final macOS ARM64 `cargo xtask check` passes 2,369 Rust tests across 291 result suites, 317 native-output fixtures, 20 examples, 63 dynamic programs, 295 atomic rejections and 64+192+231 fuzz cases. The runtime has 184 top-level tests; ThreadSanitizer passes 182 with no race reports in 11.12 s, excluding the same two long lifetime-churn tests as Decision160, which pass in the ordinary gate. Every new migration, routing, affinity and quantum regression runs under TSan. Native GC/FIFO/full-width output is identical with stealing off/reductions 1 and stealing on/reductions 8. Invalid scheduler/reduction/stealing configurations fail before source main. Seed `0x0046524e`, 5,000 steps, remains bit-identical at trace `0xd4e402a412f11e2f`, 48,739 callbacks and zero live actors, messages, heap bytes or heap objects.
* **Measurements**: The final actor comparison retains 216 observations after 36 semantic smoke checks, alongside the earlier timeout, full pre-collection matrix and 48-run focused diagnosis. Pre-transfer collection improves stealing request/reply throughput 15.4× at two schedulers and 12.6× at four, reducing the gap to pinned Morrow to 11.6% and 7.3%. Stealing still reduces lifecycle throughput; BEAM leads in-process request/reply throughput across all measured scheduler counts. Keep stealing opt-in and reductions at 1 by default. The report separates startup, full lifecycle shutdown and external completion-gap observations; these workloads do not establish OTP or general performance parity.
