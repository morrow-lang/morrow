* **Status**: Adopted for tasks 3–7 of the [multi-scheduler design](../docs/superpowers/specs/2026-09-19-multi-scheduler-execution-design.md); acceptance evidence is tracked in ROADMAP.md
* **Decision**: Each scheduler owns its mutable Session, identity slots, FIFO run queue, deadlines and fault cell. Workers own separate heap Domains; the calling scheduler uses its existing active domain to preserve main-program value ownership. Published actor headers contain immutable invocation/scheduler identity, generation, local slot, mailbox descriptor and supervision anchor, plus atomic liveness and pending-message count. Foreign readers never inspect mutable actor or scheduler state. GC registers only the owner-controlled actor region, excluding concurrent header fields. Supervision resolves its current actor through a mutex-protected weak reference, upgrading before PID allocation; stale lineage lookups remain safe without a strong reference cycle.
* **Transport**: Send preflights and copies a complete graph into an independently owned fragment on the sender. No receiver-heap entry or allocation occurs on a foreign scheduler. The receiver adopts the blocks and publishes a mailbox root before its next collection. Rejected delivery destroys the fragment and releases its committed reservation. JSON nodes are deep copies, including their reference-counted ownership; PID wrappers retain external controls. Transport publication and final draining share a short activity lock and check stop under that lock, so a copy finishing after shutdown cannot strand a reference cycle in a dead endpoint. Callbacks and payload copying run outside queue/activity locks.
* **Budget policy**: Preserve the exact invocation-wide 64 MiB logical storage budget, 1,024 live actors and 65,536 messages, with 4,096 pending plus adopted messages per actor. Use atomic reservations with rollback rather than splitting the budget by scheduler count. Preserve historical logical control charges and send error 4. Generations are global, unique and nonwrapping. Owner-local counters remain bookkeeping; shared counters are the admission authority. Physical storage includes retained controls and detached payloads and is distinct from the logical quota.
* **Drivers**: `MORROW_SCHEDULERS=1..64` selects the production count, including the calling thread; default 1 preserves existing ordering. Hosts may configure before actor publication and explicitly place root spawns. Root spawns distribute round-robin, while actor children and supervised replacements stay pinned to their spawning owner. Worker threads have their own writable fault cells and publish the first invocation fault atomically. Stop joins all workers, including partial startup, before borrowed descriptors can disappear. Global completion/deadlock requires a consistent quiescence observation; a momentarily empty live counter during supervision restart is not completion.
* **Simulation**: The feature-gated Rust scheduler-set driver activates N separate domains on one thread, selects owner turns from a bounded seed stream and records the actual scheduler-choice sequence for replay. It drives the same queue, adoption, timer and callback code as production and verifies heap edges after each turn. This is logical replay, not reproduction of OS thread timing. Single-scheduler seed `0x0046524e` for 5,000 steps remains bit-identical at trace `0xd4e402a412f11e2f` and 48,739 callbacks with zero cleanup residue.
* **Acceptance**: Full macOS ARM64 `cargo xtask check` passes 2,340 Rust tests across 290 suites, 317 native-output fixtures, 20 examples, 63 dynamic programs, 295 atomic rejections and 64+192+231 fuzz cases. The runtime library has 160 tests. ThreadSanitizer passes 158 tests with no race reports in 12.12 s; `sequential_actor_churn_reuses_slots_beyond_the_old_lifetime_limit` and `replay_survives_more_than_the_old_lifetime_identity_limit` were excluded from that sanitizer run and pass in the ordinary gate. Every new concurrent transport, GC, supervision, shutdown and startup regression runs under TSan. Independent native expected-output/ABI tests exercise three schedulers and forced precise collection. A twelve-sender, four-scheduler contention test checks all 384 messages and each sender's sequence. Fault/stop and transient-zero-live restart regressions fail before their fixes and pass afterward.
* **Consequences**: Parallel workers can execute while source main is running; opt-in parallel mode does not preserve a total cross-actor order. Message order is preserved for each sender/recipient pair. Host polling bounds calling-thread driver turns; background workers execute independently. A blocking callback still delays its own scheduler and stop until it returns. Instruction preemption, work stealing, actor migration, remote language PIDs and production BEAM/OTP parity remain outside these seven tasks. Existing scalar/immutable BEAM measurements are not actor throughput or latency evidence.
